# Zapper v3.1.17 — self-service registration with 24-hour trial

## Behavior
- New host registration is approved/active immediately; no admin approval is required.
- A **one-time trial** is started when registration is inserted into the database, not on first sign-in or first session. The subscription starts at `now` and ends exactly `now + 86,400,000ms` (24 hours).
- Registration confirmation shows the local trial end date/time. The user signs in with their new credentials immediately.
- The trial start/end are stored persistently in `users.trial_started_at_ms` and `users.trial_ends_at_ms`. `users.subscription_started_at_ms` and `users.subscription_valid_until_ms` hold the current paid/trial plan dates.
- At expiry, the subscription is switched to `inactive` in SQLite (startup, API read, and minute-by-minute sweep). The API rejects creation of **new** host sessions with HTTP 402. Account login, existing PDFs, and admin controls are not blocked.
- Email addresses are normalized to lowercase and UNIQUE in SQLite. Attempting to register an existing email (including casing differences) fails with HTTP 409. Neither login nor account recovery grants another trial.
- Admins can still activate/extend paid access through the existing user subscription/date editor. Trial history is preserved and does not reset.

## Existing accounts / persistent Railway volume
- On first startup with this version, earlier pending accounts are auto-approved and pending account status is moved to active. Disabled accounts remain disabled.
- Existing subscription values and trial history are NOT reset or granted anew. This prevents unintended renewals for existing users; admin can manually enable their subscription where needed.
- The migration adds nullable trial history columns in place. Do not delete the `/data` volume.
- Existing host-controlled meetings and participant/STT flows are not changed: a previously created PIN follows the existing host-end / maximum-duration rules; the expiry blocks **new** session creation.

## Deploy / verify
1. Commit and push the ZIP contents to the `main` branch of `shivanew-hadoop/zapper-prod`.
2. Confirm Railway `/apps/api` deploys the **new v3.1.17 commit** and Vercel deploys `/apps/web` from the same commit.
3. Register a new test email and verify it receives a full 24-hour active trial and can log in and create a PIN.
4. In an isolated/test database, verify the trial becomes inactive after 24 hours and session creation returns 402; the account can still sign in.
5. Verify the existing email cannot re-register, admin can extend the plan, and speech-to-text/session/PDF regression checks still pass.
