# Zapper v4.3.3 — Windows browser and shutdown recovery (source candidate)

**This is updated source, NOT an .exe installer, and has not been tested in a live Windows Google Meet.**

## Confirmed problems in the supplied v4.3.2 candidate

- The host and participant embedded Meet requests explicitly advertised Chrome 124. Google Meet is displaying "This browser version is no longer supported" in the reported screenshot.
- The bundled Electron 30.5.1 also shipped an obsolete Chromium 124 engine.
- Host retry automation did not explicitly detect the unsupported-browser banner, and its `getting_ready` state could repeat indefinitely.
- The overlay's X was intentionally changed to *hide* instead of exit, but there was no visible **Exit App** control; reopening the installer can detect the still-running Zapper process.

## Changes in v4.3.3

- Update desktop runtime from Electron 30.5.1 to **Electron 45.0.0 / Chromium 156**, and update electron-builder to 26.18.0. These are declared dependencies; **the actual upgraded Chromium is present only AFTER rebuilding and installing a new EXE**.
- Generate the Meet browser user-agent from the **installed Chromium runtime**, not the hard-coded Chrome 124. Do not override Google Accounts' login user-agent. Host/participant Google sign-in profiles and stored user data paths remain unchanged.
- Detect Google's *unsupported browser* warning and stop automatic host join retries with an actionable message.
- A Meet screen frozen at *Getting ready* retries at most 3 navigations after a recovery delay, then shows the window and a failure notice instead of spinning forever. Other no-progress pages stop after six navigation retries. A Google account sign-in restriction is surfaced; we cannot guarantee Google will support sign-in inside an embedded browser.
- **X** hides only the overlay and preserves background meeting/caption functionality. **Exit App** (with confirmation) or **system tray > Exit Zapper Completely** closes both Meet windows and transcription services, releases the single-instance lock and exits the process.
- NSIS install/uninstall hooks terminate a leftover `Zapper.exe` and its child processes before updating/removing application files. This does **not** clear Google session cookies or application data.
- Display desktop version **4.3.3** so the installed version can be verified from the overlay footer.

## Windows deployment / verification

1. Save ongoing transcript work and **end active meetings** first. Back up your working v4.3.1 build and deployment.
2. If an older Zapper remains running, run `apps/desktop/scripts/stop-old-zapper.ps1` in PowerShell, or execute `taskkill /F /T /IM Zapper.exe` in a terminal. This forcibly closes that desktop process and its child processes; **do not run while a live meeting must remain active**.
3. On Windows with Node.js installed: go to `apps/desktop`, run `npm install`, then `npm run check`, then `npm run dist`. Or run `build-installer.ps1`. Build must download the new Electron binary. **Reinstalling an older EXE will not update Chromium.**
4. Install the generated `dist/Zapper-v4.3.3/Zapper-Setup-x64.exe` (actual output location as generated by electron-builder). The installer closes any leftover Zapper process before replacing files.
5. Launch Zapper and check that the overlay footer shows **v4.3.3**. Create a fresh host session with overlay initially closed, confirm Meet is actually joined rather than *Getting ready*, then repeat with the overlay open.
6. Verify PIN clients, host and user captions, microphone selection, two-way chat, Hide (X), reopen from tray and **Exit App**, and finally verify no `Zapper.exe` remains in Task Manager.

**Important Google sign-in limitation:** Google can block authentication in embedded browsers irrespective of the Chromium version. If Google requires external Chrome/Edge sign-in or refuses admission, this code shows the failure rather than claiming success. An external-browser integration or revised sign-in architecture would need a separate implementation; the project cannot guarantee Google Meet admission through Electron.

- `npm --prefix apps/api run check` and `npm --prefix apps/api run smoke` — passed, backend source unchanged.
