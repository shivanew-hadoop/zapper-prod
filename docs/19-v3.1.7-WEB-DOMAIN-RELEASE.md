# Zapper v3.1.7 — responsive web portal, custom domain, and desktop releases

This update is based on the merged v3.1.6 project: professional web/auth/admin portal + latest private-cursor overlay patch. No backend session/STT/PDF behavior was changed in v3.1.7.

## Web presentation changes

- Professional fixed header with aligned desktop navigation.
- Removed the subtitle under the Zapper logo.
- Launch/Download are no longer crowded into the header; they are the primary public actions at the top of the homepage.
- Participants are explicitly told that no website login is required.
- Responsive menu keeps Home, Features, How it works, Pricing, About, Policies, Contact, Host login/sign-up and Dashboard/Logout reachable on small screens.
- "How it works" is split into two clear flows: Host and Participant, each with Step 1–3.
- Professional multi-column footer with Product, Company, Legal and support links.

## Move production website from zapper-prod.vercel.app to zapper.in

Only do this if `zapper.in` is a domain you own/control.

1. Open Vercel → `zapper-prod` project → **Domains**.
2. Choose **Add Domain** and add `zapper.in` to Production.
3. Also add `www.zapper.in` and configure it to redirect to `zapper.in` if desired.
4. Vercel shows the exact DNS records required. In the DNS provider for `zapper.in`, create exactly those records and wait for Vercel to show **Valid Configuration**.
5. Keep `zapper-prod.vercel.app`; it can remain as the Vercel fallback URL. The custom domain points to the same Production deployment.
6. In Railway → `zapper-prod` → Variables, include the new website origins:

```text
WEB_ORIGINS=https://zapper.in,https://www.zapper.in,https://zapper-prod.vercel.app
```

7. If password reset emails are enabled, set:

```text
PASSWORD_RESET_BASE_URL=https://zapper.in
```

8. In Vercel keep the API endpoint as whichever API domain is already healthy. Current project example:

```text
VITE_API_BASE_URL=https://api.zapperapp.in
```

9. Redeploy Railway if `WEB_ORIGINS` or password reset settings changed. Redeploy Vercel if Vercel environment variables changed.
10. Test `https://zapper.in`, host login, host session creation, public Launch Zapper, public Download Zapper, and Forgot Password before removing any older links from documentation.

## GitHub Releases — manual administrator upload

The public website uses a stable latest-release asset URL:

```text
https://github.com/shivanew-hadoop/zapper-downloads/releases/latest/download/Zapper-Setup-x64.exe
```

The asset filename must remain exactly `Zapper-Setup-x64.exe` for this stable URL to continue working.

### Build locally on Windows

```powershell
cd apps\desktop
npm install
npm run dist
```

The installer is created under:

```text
apps\desktop\dist\Zapper-v3.1.7\Zapper-Setup-x64.exe
```

### Upload manually in GitHub

1. Open GitHub → `shivanew-hadoop/zapper-prod`.
2. Open **Releases**.
3. Choose **Draft a new release**.
4. Create/select a new tag, for example `v3.1.7`.
5. Give the release a title such as `Zapper v3.1.7`.
6. Drag `Zapper-Setup-x64.exe` into the release assets area.
7. Publish the release as a normal release — not a draft and not a prerelease — if it should become the website's latest download.
8. Verify the stable link above downloads the newly published installer.

## GitHub Releases — automatic tagged build

The repository already contains `.github/workflows/release-desktop.yml`.

After testing and pushing source:

```powershell
git add .
git commit -m "Zapper v3.1.7 responsive portal"
git push origin main
git tag v3.1.7
git push origin v3.1.7
```

GitHub Actions builds the Windows installer and publishes `Zapper-Setup-x64.exe` to the tagged release. The website continues to use the same `/releases/latest/download/Zapper-Setup-x64.exe` URL.
