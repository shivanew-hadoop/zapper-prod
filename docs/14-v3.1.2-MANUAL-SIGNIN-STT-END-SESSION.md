# v3.1.2 acceptance notes

## Google Sign-In
The Google authentication BrowserWindow is never closed automatically. After authentication is detected, Zapper keeps the PIN form available and waits for the participant to close the Google window manually.

## STT / Deepgram
`/health` proves the key exists. `/health/stt` now performs an actual Deepgram credential validation without returning the secret. If it reports `deepgramAuthValid:false`, replace Railway `DEEPGRAM_API_KEY` with a current raw Deepgram key only and redeploy. The backend also strips the common accidental `DEEPGRAM_API_KEY=` prefix.

## Host End Session
Active sessions expose End Session beside Copy PIN. Ending makes the PIN invalid immediately. An already-connected STT socket is revalidated every five seconds and stopped. The existing participant token is still allowed to upload the completed transcript/PDF after the host ends the session.

## Participant invalid PIN
Ended, expired and unknown PINs return an explicit message asking for an active six-digit PIN from the host.
