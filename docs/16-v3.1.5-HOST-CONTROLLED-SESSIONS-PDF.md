# v3.1.5 - Host-controlled sessions and compact PDF header

## Session lifecycle

- Creating a host session sets `active=1`.
- Participant Leave/reopen does not update `active`.
- Host browser refresh only reloads state and restores the active PIN card.
- Silence and the legacy `expires_at_ms` field do not auto-end a session.
- Creating another session for the same Meet URL does not supersede older active PINs.
- Only `POST /api/sessions/:id/end` from the authenticated host changes the session to `active=0`, `status=ended`, `end_reason=host_ended`.
- Old desktop clients calling `/api/desktop/end-session` are treated as participant detach only and cannot end the host session.

## PDF

The header contains only:

- Participant email + session PIN on one compact row.
- From + To + Duration on the next compact row.

Host account and Google Meet URL are not printed. Existing transcript downloads are regenerated with this layout, while stored segment timing is retained for PDF-only pause timestamps.
