# Zapper v3.1.6 deployment notes

This is a focused update over v3.1.5. Existing Railway SQLite data and the `/data` volume remain compatible.

## Railway

Keep the existing variables and add:

```text
PASSWORD_RESET_MINUTES=30
PASSWORD_RESET_BASE_URL=https://zapper-prod.vercel.app
RESEND_API_KEY=<your Resend API key>
PASSWORD_RESET_FROM=Zapper <no-reply@zapperapp.in>
PASSWORD_RESET_RETURN_LINK=false
```

For a controlled test before email delivery is configured, set `PASSWORD_RESET_RETURN_LINK=true`; the Forgot Password response will expose the generated link in the web UI. Set it back to `false` before production.

When `zapperapp.in` becomes the production website, change:

```text
PASSWORD_RESET_BASE_URL=https://zapperapp.in
```

The sender in `PASSWORD_RESET_FROM` must be verified with the selected email provider before production email delivery will succeed.

## Vercel

No new Vercel secret is required. Keep:

```text
VITE_API_BASE_URL=https://api.zapperapp.in
```

Deploy from `apps/web`. The following public payment-review pages will be available automatically:

- `/terms.html`
- `/privacy.html`
- `/billing.html`
- `/refund.html`
- `/contact.html`

## Desktop

Rebuild the installer from `apps/desktop`:

```powershell
npm install
npm run dist
```

The installer output remains `Zapper-Setup-x64.exe` under `apps/desktop/dist/Zapper-v3.1.6/`.

## Verification

1. Start a participant session and confirm live transcription is visible.
2. Click Google Sign-In during the live session. The live screen must remain active.
3. If the join panel is ever shown while the session token is still active, click **Back to Live**.
4. Test Forgot Password using a registered host email.
5. In Admin > Manage user, set a new password and confirm that user can log in with it.
6. Open every public policy URL directly without logging in.
7. Log into host/admin and use the persistent top navigation to view public sections without losing the login token.
