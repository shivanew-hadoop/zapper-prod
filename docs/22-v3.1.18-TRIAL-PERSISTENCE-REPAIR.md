# Zapper v3.1.18 — 24-hour trial database persistence repair

## What this version changes
- Fresh self-service registration persists account active/approved, `trial_started_at_ms`, `trial_ends_at_ms`, `subscription_status=active`, `subscription_started_at_ms`, and `subscription_valid_until_ms`. Start time is the registration timestamp; end time is exactly 86,400,000 ms later (24 hours).
- Adds a SQLite `AFTER INSERT` trigger as a database-level safety net if an older registration writer creates a host without trial/subscription dates. The trigger is idempotent for accounts with populated dates and does not override subscriptions, historical trials, administrators, or disabled users.
- On backend startup only, repairs recent (within the previous 24 hours), un-used host registrations that were created with no subscription dates, no trial history, and no host sessions. The trial is calculated from the ORIGINAL registration timestamp (not restart time). Existing subscriptions, old/disabled accounts, and users with previous host sessions are not changed.
- Registration success messages in the web app are displayed only when the API confirms active access with both dates; duplicate emails are rejected, including case variants of an existing legacy email.
- Adds `version` to `/health` so production can be checked without access to admin credentials or private data.

## Production verification — do not delete or reset `/data`
1. Push version 3.1.18 source to the GitHub `main` branch. Confirm Railway `apps/api` and Vercel `apps/web` deploy the same new commit; merely uploading a ZIP is not deployment.
2. Open `https://api.zapperapp.in/health` and verify the JSON contains `"version":"3.1.18"`. If not, production still runs old API code; stop and fix deployment first.
3. Register a NEW email. In the admin dashboard, confirm **Active** and both dates including time, 24 hours apart. Sign in and create a host session.
4. Check any previously broken registration created within 24 hours of the updated API starting. If its trial/date fields were never set and it has never created a host session, the backend repairs it based on the original registration time. Accounts older than one day are not automatically credited; an admin can set their subscription manually.
5. Confirm re-registering the same email is rejected, a 24-hour trial expires automatically, and admin renewal still functions.
